## What to include in your report

To help us triage and fix the issue quickly, please include:

- A short summary of the issue and the impact.
- Step-by-step instructions to reproduce (or a proof-of-concept), including environment details (OS, browser, versions).
- Expected vs actual behavior.
- Any exploit code, logs, or screenshots (encrypted if sensitive).
- If you believe a compromise already occurred, the timeframe and any indicators of compromise.

## Response and Timeline

We will acknowledge your report within 7 calendar days. Our typical timeline for triage and a public fix depends on the issue severity:

- Initial acknowledgement: within 7 days
- Triage and classification: within 14 days
- Fix, coordinated disclosure, or mitigation: typically within 30–90 days depending on complexity

If the issue requires additional time, we will keep you informed.

## Disclosure Policy

We follow a coordinated disclosure approach:

- Please do not publicly disclose the issue until a fix has been released or we have otherwise agreed on a disclosure timeline.
- If you disclose publicly before a coordinated disclosure, we reserve the right to update or alter the mitigation steps and timeline.

## Severity Classification (guidance)

- Critical: Remote code execution, full system compromise, or issues that could lead to severe data loss or exposure.
- High: Authentication bypass, severe privilege escalation, or significant data exposure.
- Medium: Information disclosure with limited impact, or vulnerabilities requiring conditions that significantly limit exploitation.
- Low: Minor issues, cosmetic or informational issues with little security consequence.

## Supported Versions

This repository is a personal portfolio site. If your report concerns an external dependency or specific version of a package used here, please include the package name and version in your report. We will patch or update dependencies as needed.

## CVE Requests

If you believe the issue warrants a CVE, mention this in your report. We will work with the appropriate CNA (CVE Numbering Authority) or request a CVE when appropriate.

## Safe Harbor / Good Faith Research

Security researchers acting in good faith to improve security are welcome. Please avoid any destructive actions (deleting data, altering content, or impacting availability). We will not pursue legal action against researchers who follow this policy.

## Acknowledgements

If you would like credit for reporting a vulnerability, let us know and we will add your name (or handle) to an acknowledgements list unless you request anonymity.
